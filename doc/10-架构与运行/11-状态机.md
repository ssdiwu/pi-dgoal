# 11 - 状态机

> 当前权威：ADR 0051；结构化活性熔断继承 ADR 0045。状态写入统一经 `work_update`，check 只记录审核事实。

## Goal 状态

```text
soft:                  active ──all terminal + real Phases done──→ done → null tombstone

high assurance: pending ──proposal confirmed──→ active
                                          │
Execution:                                ├── completion guards + work_update ──→ done → tombstone
Goal/Staged Check:                        ├── required checks + work_update ────→ done → tombstone
                                          └── technical/user blocker ──→ paused ──resume──→ active
```

| 状态 | 含义 |
|---|---|
| `pending` | Goal Check / Staged Check 正在语义预审或等待用户确认 |
| `active` | soft Work List 或 Plan Contract 正在推进；business rejection 也保持 active |
| `paused` | 仅 Plan Contract 使用；continuation 停止，等待恢复 |
| `done` | 完成事实已写；随后立即用 null tombstone 清除 current Goal |

完成事务顺序固定：done → null tombstone → continuation / proposal / 熔断 / check snapshot / 授权清理 → UI 后效。TUI 失败不回滚状态；工具返回结构化完成总结。

## Work Item 状态

```text
pending ──→ in_progress ──→ done
   │              │
   ├──────────────┴──→ blocked ──→ in_progress
   └─────────────────→ abandoned
```

- `done` / `abandoned` 为 terminal 且不回退。
- 计划态 done 必须有 evidence；声明 deliverables 后必须逐 target 有 deliverableEvidence。
- blocked 必须有 blockedReason；abandoned 必须有 abandonedReason。
- 未终结依赖阻止 Work Item 推进；依赖不能成环或指向未来 Phase。
- soft Work Item 可省略 Description / evidence；进入 Plan Contract 前必须原子归一。

## Phase 状态

```text
pending ──→ in_progress ──完成守卫 + work_update──→ done
   │              │
   └──────────────┴──→ blocked ──→ in_progress
```

- 多个 Phase 严格串行；后续 Phase 不能越过第一个未 done Phase。
- Work Item 开始可使 Phase 进入 in_progress，但成员耗尽永不自动 done。
- soft / Execution / Goal Check：成员全部 terminal 后可由 `work_update(target=phase,status=done)` 显式完成。
- Staged Check：还要求当前 Phase local revision 的 `phase_check=approved`。
- Staged Check 的 Phase backbone 冻结且 done 不回退；全部 Phase 显式 done 后，可新增由最终 `goal_check` 覆盖的 goal-level 根 follow-up。只要还有 open Phase，就不能用根 Work Item 绕过 Phase check。

## CheckRecord

```text
running → approved | rejected | audit_error
```

- phase check 绑定 `WorkPhase.revision`；goal check 绑定 `WorkList.revision`。
- approved 只允许后续 update 通过守卫，不自动 done。
- rejected 保持 Goal active；修复使相关记录失效后重审。
- audit_error 是技术失败，Goal 进入 `paused(audit_error)`。
- session generation、Goal ID 或 revision 改变时，迟到结果丢弃。

## Revision

- 每次 Work List 持久 mutation 令 `WorkList.revision` 单调增加，并清理不再适用的 goal check。
- Phase subject / description、非 done 状态或 blocked reason 等 local audited facts 改变时增加 `WorkPhase.revision` 并清理该 Phase check；approved 后到 done 的显式收口保留 local revision，无关 Phase approval 不失效。
- Plan Contract `revision` 始终匹配当前 Work List revision；Profile transition 记录当时 revision 且只允许升档。
- 纯读不改变 revision；check 写审核事实，但不会替代 update 完成事务。

## Paused 与技术熔断

soft Work List 没有 paused 或 continuation。Plan Contract 保留固定可靠性出口：

| `pauseReason` | 来源 | 恢复 |
|---|---|---|
| `user_abort` | 用户中断高保障执行或 `/dgoal pause` | `/dgoal resume` |
| `model_error` | 连续第 5 次主模型错误 | Execution 可由精确绑定的真实 interactive/RPC 输入恢复；更高 Profile 显式 resume |
| `audit_error` | 审核候选耗尽、协议异常或 timeout | resume 后清理故障 scope 并重试 |
| `no_progress` | 连续 3 轮无工具，或 8 轮只有 activity 无 durable progress | Execution 可重组/满足守卫后关闭；否则显式 resume |
| `agent_blocked` | `work_update(target=goal,status=paused,reason=...)` | 用户解决 blocker 后 resume |

`no_progress` 是结构化活性保护，不是语义审核。运行时不读取 assistant 文本、不解析 `bash` 字符串；成功文件写入、Work List status/evidence/dependency/集合变化与独立 check 终态算 durable progress。只读、失败写入、未知工具、无终态 check、仅改标题/Description 与 no-op 只算 activity。

## 关闭与自动收口

**soft**：全部 Work Item terminal 且所有真实 Phase done 时，由成功的 item / phase update 在同一次工具调用中自动收口；无 Work Item 的空清单不会自动完成。

**Execution**：全部 Work Item terminal、真实 Phase done，且 `summary` / `verification` 非空后，`work_update(goal,done)` 收口。

**Goal Check / Staged Check**：在上述基础上，还要求当前 Work List revision 的 goal_check approved；Staged Check 的每个 done Phase 已分别通过对应 local revision 的 phase_check。

关闭后 Current 状态为空；Plan Contract 可先归档到 Plan Run History。History 只读、去重、不可 resume，也不跨 session 分支继承。
