# 10 - 建检循环、Work List 与保障结构

> 当前权威：ADR 0051。术语以 `../术语表.md` 为准。

## 两个正交维度

dgoal 不再用 Plan 类型同时决定内容树和保障。当前模型由两个独立维度组成：

1. **工作结构**：一个 Goal 拥有一份 Work List；Work Item 可平铺，也可放进按真实边界创建的非嵌套 Phase。
2. **保障 Profile**：soft、Execution、Goal Check、Staged Check 决定 continuation 与独立建检密度。

| Profile | continuation | Phase 要求 | phase check | goal check |
|---|---:|---|---:|---:|
| soft | 否 | 可选 | 否 | 否 |
| Execution | 是 | 可选 | 否 | 否 |
| Goal Check | 是 | 可选 | 否 | 是 |
| Staged Check | 是 | 至少一个真实 Phase | 是 | 是 |

Plan Contract 只允许 `execution → goal_check → staged_check` 单向升级，并保留 Goal、Work List、ID、终态、证据与 Plan Run identity。soft → 任意 Profile 是增加保障；不存在隐藏 Phase 或永久双轨。

## 建检循环

建检循环是“执行与独立判卷分离”的验证约束：

1. 主 agent 通过 Work Item 推进并记录可复验证据。
2. `phase_check` / `goal_check` 在 fresh context 的隔离 Pi 子进程中核验冻结条件。
3. check 只写当前 revision 的 CheckRecord，不写完成状态。
4. `work_update` 根据当前 Profile 与 CheckRecord 决定是否允许写 Phase / Goal done。
5. rejected 后继续修复；相关 revision 变化使旧 approval 失效，迟到结果被丢弃。

soft / Execution 没有独立 check；前者在全部工作终结后自动收口，后者由主 agent 显式关闭 Goal。

## 内容层级

- **Goal**：全局方向、Description 与生命周期；只拥有一份 Work List。
- **Work List**：根 Work Item + 可选真实 Phase；不是 Plan Contract。
- **Phase**：严格串行的组织边界，只包含 Work Item；成员耗尽不自动 done。
- **Work Item**：实际执行单元，带 status、Description、evidence、blockedBy 与可选 deliverables。

Description 是执行说明，不是平行验收契约。硬方法边界进入 `guardrails`，必须达到的独立结果进入 `acceptanceCriteria`，主观体验进入 `userReviewItems`。

## Work Item DAG 读模型

`blockedBy` 构成 plan-global Work Item DAG。运行时纯派生：

- **ready**：未终结、未显式 blocked，所有直接依赖均 terminal，且所属 Phase 是当前可推进 Phase；
- **waiting**：仍有未终结直接依赖，或所属 Phase 尚未到达；
- **root blockers**：沿未完成依赖递归可达的显式 blocker 与原因；
- **unblocks**：某 ready Work Item 单独完成后会立即解锁的直接后继。

该投影进入 `work_read`、`/dgoal s` 与主 agent context，不进入持久态。ready 只表示依赖满足，不保证并行安全；主 agent 仍负责范围冲突、结果核验与状态写入。

## 双可见性轴

| 内容 | 用户 TUI | agent context |
|---|---|---|
| Goal | heading + Status 详情 | objective + Description |
| 真实 Phase | 标题常驻，详情可展开 | 当前/未来完整；done 后仅标题 |
| Work Item | 当前项默认可见，详情含证据/依赖 | soft 或计划态执行说明 |
| Plan Run History | History tab / `work_read(history)` | 默认不注入执行 prompt |

done Phase 的软遗忘只影响执行 context；持久化、TUI 与 History 继续保留结构化事实。

## 完成链

```text
soft
  work_list → work_update(item) × N
  → all items terminal + all real phases explicitly done
  → auto close + completion summary

Execution
  execution_plan → work_create/work_update
  → work_update(phase,done) × N → work_update(goal,done)

Goal Check
  goal_plan + confirmation → work_update
  → goal_check → work_update(goal,done)

Staged Check
  staged_plan + confirmation
  → [work_update(item) → phase_check → work_update(phase,done)] × N
  → goal_check → work_update(goal,done)
```

**不变量**：approved 只是审核事实；只有 `work_update` 改变 Phase / Goal 完成状态和完成显示。
