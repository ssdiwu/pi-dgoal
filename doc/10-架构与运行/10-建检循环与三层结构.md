# 10 - 建检循环与三层结构

> 当前权威设计：ADR 0038 + ADR 0042。术语以 `../术语表.md` 为准。

## 三档 Plan

三档 Plan 共享 goal / phase / task、持久化、TUI 与自动续跑，只改变激活边界和独立审核密度：

| Plan | 用户确认 | phase check | goal check |
|---|---:|---:|---:|
| Task Plan | 否 | 否 | 否 |
| Phase Plan | 是 | 否 | 是 |
| Goal Plan | 是 | 是 | 是 |

Task Plan 使用一个隐藏 phase 复用内部结构，但工具、prompt 和 TUI 都只暴露平铺 task。Phase/Goal Plan 的 phase 在启动时冻结，运行中只允许新增 task。

## 建检循环

建检循环是“执行与独立判卷分离”的验证约束：

1. 主 agent 按 Plan 推进并提供可复验证据。
2. `phase_check` 或 `goal_check` 在 fresh context 的隔离 Pi 子进程中核验冻结条件。
3. check 只写审核记录，不写完成状态。
4. `plan_update` 根据当前 Plan 类型和最新审核记录决定是否允许写 done。
5. rejected 时继续修复；计划一变化，旧 approved 自动失效，再次 check。

Task Plan 没有独立 check，完成守卫验证 task 状态/evidence、可选交付物的逐项 evidence，以及最后一个 task 的同会话 completion review。Phase Plan 只有 goal 级建检。Goal Plan 同时有 phase 与 goal 建检。

## 三层内容

- **Goal**：全局方向、Plan 类型、冻结验收契约与生命周期；必填 Description 说明目标理由与方法边界。
- **Phase**：阶段主干；用户可见 phase 使用必填 Description；Task Plan 的 phase 是内部隐藏容器，不生成独立用户说明。
- **Task**：按需分解的执行单元，带必填 Description、状态、evidence 与 `blockedBy` 依赖；可选 `deliverables` 显式声明跨文件、命令或外部状态交付，声明后 done 必须带一一对应的 `deliverableEvidence`。

Description 是主 agent 的权威执行说明，不是平行验收契约。必须阻止的方法进入 `guardrails`，必须达成的方法性结果进入 `acceptanceCriteria`。Task Plan 的最后一个 task 会在同一 `plan_update` 用 `completionReview` 回读所有 Description 与声明交付物；它仍是主 agent 自检，不是独立审核。

phase 不是普通工作面分组。只有真实中间里程碑才值得放进 Goal Plan 并冻结 phase 验收条件；代码、测试、文档通常是同一 phase 下的 task。

## Task DAG 读模型

`blockedBy` 已经让 task 构成 DAG。运行时只对当前未完成 phase 派生四类解释：

- **ready**：当前 phase 本身未 blocked；task 未 done、未显式 blocked，且所有去重后的依赖已 done。pending 与 in_progress 都可出现在这里；
- **waiting**：仍有未完成直接依赖；
- **root blockers**：沿未完成依赖递归可达的显式 blocked task 与原因；
- **unblocks**：若某 ready task 此刻单独完成，会因“唯一未完成依赖被满足”而立即 ready 的直接后继。

该读模型由 `plan_read`、`/dgoal s` 与 `<dgoal_task_graph>` prompt block 共用，不进入 Plan 持久态，也不改变 phase 顺序守卫。ready 集合只声明主 agent 当前合法执行或委派的 task；它不选择执行工具，也不表示 task 之间可安全并发。主 agent 仍需核对范围冲突、裁决结果 evidence，并通过 `plan_update` 落状态。

## 双可见性轴

| 内容 | 用户 TUI | agent context |
|---|---|---|
| Goal | heading 可见；完整 Description 在 `/dgoal s` 列表页 | objective + Description 可见 |
| Phase/Goal Plan 的 Phase | 标题默认可见；Description 在确认 UI / `/dgoal s` 详情页 | 当前/未来 Description 可见 |
| Task | Task Plan 默认可见；Phase/Goal Plan 默认折叠；Description 在工具结果 / `/dgoal s` 详情页 | Description 可见 |
| Task Plan 隐藏 Phase | 不可见 | 不可见 |

Phase/Goal Plan 的 done phase 在每轮 context 中软遗忘其 task，只留 phase 标题；持久化与 `/dgoal s` 仍保留完整细节。

## 完成链

Task Plan
  task_plan
  → plan_update(task, done) × N
  → final task evidence + declared-deliverable evidence + completionReview
  → automatic goal closure

Phase Plan
  phase_plan + 用户确认
  → plan_update(phase, done) × N
  → goal_check
  → plan_update(goal, done)

Goal Plan
  goal_plan + 用户确认
  → [phase_check → plan_update(phase, done)] × N
  → goal_check
  → plan_update(goal, done)
```

**不变量**：approved 只是审核事实；只有 `plan_update` 可以改变完成状态和完成显示。
