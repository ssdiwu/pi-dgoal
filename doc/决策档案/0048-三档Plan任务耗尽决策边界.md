# ADR 0048：三档 Plan 任务耗尽决策边界

> Status：已接受，已实现。

## 背景

Task 是当前目标与证据下最小的可验证行动，不是预先穷尽的待办项。ADR 0047 已将 Task Plan 的 task 耗尽改为主 agent 决策边界；Phase Plan 与 Goal Plan 的当前 phase 在 task 耗尽后仍直接提示 phase done 或 phase check，造成三档 Plan 对同一事实的推进语义不一致。

## 决策

1. 三档 Plan 的当前 task 全部带证据完成时，统一先形成主 agent 决策边界：把已有 evidence 与当前 scope 的 Description、适用的交付物/冻结契约及最新 rejected feedback 比较；只有发现可精确表述的未覆盖差距时才用 `plan_create` 新增 task，否则确认当前 scope 已足够后进入既有完成链。
2. Task Plan 的 scope 是 goal：新增 task、整份 `task_plan` 替换，或显式 `plan_update(target=goal,status=done)`。
3. Phase Plan 的 scope 是当前 phase：新增当前 phase task，或 `plan_update(target=phase,status=done)`；所有 phase done 后仍遵循 `goal_check → goal done`。
4. Goal Plan 的 scope 是当前 phase：新增当前 phase task，或 `phase_check → phase done`；所有 phase done 后仍遵循 `goal_check → goal done`。已有 phase check rejected 继续优先产生接续 task。
5. 这只是主 agent 的选择顺序与 frontier 投影，不增加状态、Plan 类型、公共工具、调度器或自动 Git 动作；check 与显式 update 的完成守卫不变。

## 后果

- 候选—观察—比较—学习内循环统一负责“下一个 task 是否应存在”：task 是候选，evidence 是观察，主 agent 对照当前 scope/契约/反馈作比较，新增 follow-up task 或进入完成链是学习后的合法 Plan 演化；不另存实验历史或学习记录。
- `ready` 仍只表示 task 依赖满足；task 耗尽的 frontier 明确展示“继续生成 task”与“进入既有建检链”的二选一路径，不替主 agent 作语义判断。
- ADR 0047 的 Task Plan 专项结论保留，本 ADR 将同一边界推广到 Phase Plan 与 Goal Plan。
