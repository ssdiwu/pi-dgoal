# 30 - 项目路线图

> dgoal 演进计划。v0.8.1 当前架构以 ADR 0051、`../10-架构与运行/` 与 `../40-版本实施方案/44-v0.8.1-单一工作清单与计划保障实施方案.md` 为准。

## 当前阶段：v0.8.1 单一 Work List 架构已落地

v0.8.1 已把结构层级与保障强度拆开：每个 Goal 只有一份 Work List；Phase 只在真实串行边界存在；同一 Work List 可保持 soft，或单向升级 Execution / Goal Check / Staged Check Plan Contract。v0.8.1 之前的结构、公共工具与活动持久态不再构成生产路径。

### v0.8.1 已实现主干

1. **软性 Work List**：跨 turn 持久化但不续跑；Work Item 可先保持轻量，全部终结且真实 Phase 显式完成后自动收口并返回总结。
2. **Execution Plan**：平铺或真实 Phase 的 Until Done；计划态 Description、evidence 与 deliverableEvidence 守卫；固定模型错误与 3/8 no-progress 熔断。
3. **Goal Check Plan**：可零 Phase；用户确认后冻结 goal acceptance contract；`goal_check` 与 `work_update(goal,done)` 分离。
4. **Staged Check Plan**：至少一个真实、非嵌套、严格串行 Phase；逐 Phase local revision 建检，再做 goal 终审。
5. **九个公共工具**：`work_list` / `execution_plan` / `goal_plan` / `staged_plan` / `work_create` / `work_read` / `work_update` / `phase_check` / `goal_check`。
6. **单一持久路径**：当前态使用 `dgoal-work-v1`；v0.8.1 之前的活动状态不读取、不迁移；跨 session 分支以 generation + Goal ID + revision 隔离迟到审核与 continuation。
7. **Plan Run History**：当前 session 分支内 append-only 终态快照，TUI Current / History 统一浏览；历史不含 auditor 原始报告、feedback、thinking 或 transcript。
8. **统一 TUI 与 prompt 投影**：Profile / Work Item / 真实 Phase 使用同一投影；done Phase 在执行上下文只留标题，详细状态与 History 仍保留。
9. **可靠关闭**：所有 Profile 收敛到 done → null tombstone → 全运行态清理 → UI after-effect；返回 `dgoal 完成信号`，不遗留已完成清单。
10. **现有安全不变量保留**：显式高保障授权、语义预审、check/update 分离、审核候选链与 checkpoint、迟到结果失效、TUI fail-soft、目标项目测试权威。

## 当前工具链

```text
建立 / 升级：work_list / execution_plan / goal_plan / staged_plan
管理：       work_create / work_read / work_update
审核：       phase_check / goal_check
```

### 典型链路

```text
soft：work_list → work_update(item) → 自动清理与总结

execution：execution_plan → work_create/work_update → work_update(goal,done)

goal check：goal_plan → work_update → goal_check → work_update(goal,done)

staged check：staged_plan
→ [work_update(item) → phase_check → work_update(phase,done)] × N
→ goal_check → work_update(goal,done)
```

## 发布与验收收尾

1. 自动门禁：`npm run test:rpc`、`npm run test:context`、`npm test`、`npm run test:smoke:runtime`、TypeScript 编译。
2. 真实模型 smoke 只在获得 token 授权后运行；先跑 runtime / cleanup 定向 smoke。
3. 启动确认、Current / History Modal、浮层、错误回环与完成总结仍需真实 Pi TUI 人工复核。
4. 发布时明确告知：旧活动 Plan 不迁移，升级后需重新建立 Work List。

## 历史里程碑

- **v0.2–v0.5**：Goal / Phase / Task 三层、reducer、浮层、启动闸门与独立审核基础。
- **v0.5.7–v0.6.4**：审核候选链、冻结验收契约、隔离 runtime、语义预审 idle timeout、checkpoint 与主动暂停。
- **v0.7.x**：曾以 Task / Phase / Goal Plan 和八工具表达结构与保障；引入 Description、交付物证据、Task DAG、3/8 熔断和模型错误恢复。
- **v0.8.0**：Pi 0.83 与 strict schema 可空兼容基线。
- **v0.8.1**：ADR 0051 单一 Work List + 正交 Plan Contract + 九工具 + Plan Run History。

详细版本时间线见 `../../CHANGELOG.md`；历史 ADR 不改写过去，但索引必须标明当前覆盖关系。

## 后续候选

- **History 可观测性**：若真实使用需要，再展示运行次数、审核耗时或更细筛选；不恢复原始 auditor report。
- **ObservableOperation 公共骨架**：语义预审和独立审核已有两套 idle-timeout；第三个同类场景出现后再抽取。
- **evidence 结构化**：当前保持文本；只有稳定解析命令、工件与预期输出的需求出现后再设计。
- **Work List 编辑体验**：基于真实 TUI 使用反馈再考虑批量编辑或更丰富筛选，不增加第二张状态表。

## 暂不做 / 远期

- 跨 session 后台 Goal、多 Goal 池、定时/事件调度。
- 任意深度内容树；依赖继续使用 Work Item `blockedBy` DAG。
- 自动 Git commit、rollback、push、publish、部署或删除。
- 替代项目自身测试命令。
- 为想象中的 provider / adapter 提前建接口。
